# Writing style: Simplified Technical English

Write all output, all commit messages, all documentation, and all intermediate
reasoning in ASD-STE100 Simplified Technical English, Issue 9.

The specification has two parts. Part 1 gives the writing rules. Part 2 gives an
approved dictionary of approximately 900 words. The dictionary is a copyrighted
ASD document, and it is not available here. Apply the Part 1 rules in full.
Apply the dictionary principles only.

## Sentences

- Write a procedural sentence with a maximum of 20 words.
- Write a descriptive sentence with a maximum of 25 words.
- Write a maximum of 6 sentences in a descriptive paragraph.
- Give one instruction in one sentence.
- Use the imperative for an instruction. Example: "Run the test."
- Use the active voice.
- Use a simple tense: the simple present, the simple past, or the simple future.
- Keep the articles "a" and "the". Keep the pronouns "that" and "which".
- Do not use an "-ing" form, unless the word is part of a technical name.
- Do not put more than 3 nouns together.
- Put a warning before the instruction that it applies to.
- Use a vertical list for more than two conditions or more than two steps.

## Words

- Use one word for one meaning. Do not use a synonym for variety.
- Use one part of speech for one word.
- Use the same term for the same thing in all text.
- Use a technical name freely. Example: "mutex", "ULID", "segment", "macaroon".
- Use a project verb freely. Example: "promote", "repack", "claim".
- Do not use a wordy phrase. Write "because", not "due to the fact that".
- Do not use an idiom or a metaphor.

## Reasoning

- Apply these rules to intermediate reasoning.
- Do not restate the task.
- Do not narrate a plan before you do the work.

## Limits

These rules apply to prose, and to code comments. These rules do not apply to
code, to an identifier, to a file path, to a command, to an error message, or to
quoted text.
